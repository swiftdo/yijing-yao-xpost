# 完整约定与填写细则

## 1. 图文分工

| | 承担 | 不承担 |
|---|---|---|
| 帖子（主） | 首行标识、误读纠偏、当下处境、具体动作与画面 | 不列卦象图、不列爻位术语、不抄《象》《文言》原文，不写看图提示，不做说教 |
| 卡片（补充） | 六爻卦图、本爻高亮、爻辞与《象》原文**及其白话译文**、《文言》节引、「所处之位」三条、对照行 | 不抒发、不写金句、不重复帖子的白话义理 |

**译文的位置分工**：帖子里只出现**已经被白话讲清**的文言词句（见 2.5）；逐句译文一律放在卡片上，因为帖子只有 280 加权字符，装不下。卡片采用古籍经注格式——原文大字、译文小字紧随其下，读者不必自己转译。

同一义理允许两边都出现，但必须**换一套说法**：帖子用白话，卡片用术语与原文＋译文。唯一的有意重复是帖子首行（标识锚点）。

## 2. 帖子逐段规则

```
第 1 行   卦 · 爻｜爻辞                 ← 固定，三样信息一次给全
空行
翻转      这爻常被怎么误读 → 更准的读法    ← 帖子的信息增量，一到两句
空行
主体      1～3 段具体处境、动作、画面      ← 从读者能对上的场景切入
空行
收束      一句画面，或一句判词            ← 不指向下一爻
空行
标签      #周易 #某卦
```

### 2.0 通顺优先（凌驾其余各条）

一条帖子先要像人说的话，再谈信息增量。写完朗读一遍，凡是要停一下才顺的地方，就是没通顺。

- **主谓齐全**：每个分句说清「谁·做什么」。别把三个主语挤进一句、靠逗号硬并。
  - ✗ `田不是朝堂，有德有才，位置还在原处。`
  - ✓ `田不是朝堂。人有德有才，位置却还在原处。`
- **一句一个意思**：该断句就断句，不靠逗号串。
  - ✗ `常来往的还是几个肯说实话的人，手上的事一件件交出去。`
  - ✓ `常来往的还是几个肯说实话的人。手上的事，一件件交出去。`
- **分句之间要有关系**：因果、转折、时间，用「所以／但／等到／后来／反倒」接住；没有关系的两句，别放进同一句。
- **破折号全篇 ≤1**：它是补语，不是万能连接。
- **不写旁白**：解释「这一爻在讲什么」的句子会打断场景；这类观察要么并进翻转句，要么删掉。
- **不必写满 280**：220～275 都算正常；为凑字数加的句子最先删。

### 2.1 翻转句（信息增量；找不到真误读就做单字重译）

一条帖子光有处境不够——那是抒情；读完要么改了看法，要么什么也没留下。**翻转句（或单字重译）就是那个「改了看法」**：

- **是什么**：`「终日乾乾」常被当成励志句。它写的不是勤奋，是不敢停。` 先摆出这爻最常见的读法，再给出更准的读法。
- **为什么不算说教**：它判断的是**文本**，不是读者。说「这四个字常被读成防微杜渐」是在纠一个解法，说「你不该急功近利」才是在教训人。前者是信息，后者是训话。
- **必须是真的**：搜一次白话解读，确认大众版本确实这么说（多半是励志化或道德化），再写。不许为了凑一个翻转而编造误读。
- **要短，且第二句必须落在判断上**：翻转段只有两句，第二句就是落点——这个判断同时是关键词的白话（例 4：`那个「或」是「也许」`）。读者读完要知道「所以呢」，答案就是场景第一句要说的事。
- **不在翻转段里逐字下定义**：`X 是 A。Y 是 B。Z 是 C。` 排着来是术语课，不是纠偏。爻辞里的字翻不过来，只翻最要紧的那一个，其余交给场景和收束去说；逐字铺陈（「草木长、有四方、载得住」这种）塞进翻转段只会把它变成注释。
- **翻转句本身用白话**：别用「《文言》说『或之者，疑之也』——拿不准，不是拿得稳」这种文言＋训诂对照，读者要先解一句古文才明白你的意思；同一层意思写成「其实那个『或』是『也许』——上得去，也可能还在原地」。**判断要落在白话上，不要落在考据术语上**。
- **找不到明显误读时**，改用**单字重译**：抓爻辞里一个关键词，用现代口语把它拆开。例：九二的「见」拆成「被看见」与「被任用」——`见，也不等于用。`

### 2.2 从读者角度写（主体段）

主体不写「他站在边上」，写读者桌上正在发生的事。差别不在人称，在**要不要读者先把自己搬进画面**：

| 写法 | 例子 | 判断 |
|---|---|---|
| ✗ 第三人称意象 | `脚已经站到边上，再一步就上去了。` / `退路留着。上面那扇门只开一条缝。` | 意象不差，但读者得先代入才成立 |
| ✓ 读者自己的场景 | `桌上那份 offer 还没签，笔帽没拔。` / `有人问起，只说再看看。` / `夜里躺下，想的不是去了怎么干，是万一不成怎么回来。` | 一句就对上了自己的事 |

- 场景要**具体到能看见**：笔帽、闹钟、名片、桌上那份还没签的东西。抽象的动作（「犹豫」「纠结」）不算画面。
- 挑最常见的那一种处境即可（跳槽、竞聘、被问到要不要接），不要罗列。
- 仍然不说教：只写真发生的动作与心里的盘算，不写「所以你应该」。

### 2.3 收束：画面或判词（不写接续句）

结尾只做一件事——把处境收在一个看得见的点上，或者落一句从文本里读出来的判词：

- 画面：`桌上那份 offer 还没签，笔帽没拔。`、`闹钟定在六点，睡前又核对了一遍。`
- 判词：`爻辞给的判词是「无咎」：没定，不算错。`
- **不写「再往上一步是九四：那一步，是跳」这类接续句**。单篇读完就够了，多这一句只是把读者从处境里拽出来报进度；连载的事交给读者自己往上翻。
- 判词必须来自爻辞（如「无咎」→「不算错」），不是作者下的结论；不预告吉凶、不写箴言式金句、不写「下期见」。

### 2.4 首行与语气

- **首行格式**：`卦名 · 爻名｜爻辞全文`。例 `乾 · 九二｜见龙在田，利见大人`、`乾 · 九三｜君子终日乾乾，夕惕若厉，无咎`。用全角竖线 `｜`。
- 首行已含爻辞，正文不要再说「这一爻叫某某」——那句是冗余，加首行后必须删。
- **语气：同路人的见闻，不是长辈的叮嘱**。**不劝告、不下指令、不下判断**：
  - 禁用「切忌／必须／切记」，也**不用「宜」「不必」「应该」「要记得」「就够了」「能做的只有一件」**——这些同样是在教人做事。
  - 少用「这一爻讲的是 X」「说明了一个道理」「难的从来不是 A，是 B」这类全知口吻；判断留给读的人。
  - 注意：**翻转句不在此列**。说「这四个字常被读成 X」判断的是文本，不是读者，正是允许的那种判断。
  - 改用具体的处境、动作、画面：写「话传得比人快，位子没跟上」，不写「不必争名分」；写「有人蹲下来看了看，然后照旧赶路」，不写「顺着它看一眼就够了」。
  - 结尾用画面或判词收束（见 2.3），**不写箴言式金句**、不给分寸提醒。
- **避开**：鸡汤腔、排比堆砌、「在这个快节奏的时代」类套话、AI 味总结句、教训口吻。
- **标签**：固定 2 个，`#周易` + `#某卦`（如 `#乾卦`）。不要第三个。
- **不写看图提示**：已废弃「卦象与原文见图」这类占位句——附图本身已说明，无需在正文里再提一次。删掉它省下约 18 加权字符，**用来把处境、动作写具体**（如「这时候没人替你兜底」），篇幅别空着，也别塞套话凑数。
- **两种可选风格**：**翻转版**（默认，误读纠偏 + 处境白描，传播性最好）／**克制随笔版**（没有明显误读时改用单字重译，篇幅更短、更贴作者气质）。默认给翻转版即可，用户要备选再给第二版。

### 2.5 引文言必译

帖子里引用任何文言词句（爻辞片段、「勿用」「君子」之类），**必须在同一段内用一句白话说清它指什么**——不留给读者自己猜。例：

> 「勿用」是没人用，「利见」是有人肯见。中间隔着的不是本事，是时位。

- 首行已经给出整句爻辞，那是标识，不算「引用」，不必翻译。
- 翻转句里引的那四个字（如「终日乾乾」）算引用，翻转句的后半句通常就是它的译文（「它写的不是勤奋，是不敢停」），不必再加一句。
- **逐句译文不上帖子，只上卡片**：280 加权字符装不下，硬塞会把处境与画面挤掉。帖子负责「懂了什么」，卡片负责「原文怎么讲」。
- **判词也要译**：`无咎`／`厉`／`悔` 这类断语读者未必真懂，收束句里用了就顺手翻掉——`爻辞给的判词是「无咎」：没定，不算错。` 不译等于把最要紧的一层留给读者猜。

## 3. X 字数规则（必核）

X 的 280 是**加权字符数**，不是字数：

- 拉丁字母、数字、ASCII 标点、换行 → 1
- CJK 汉字、中文标点、全角符号、emoji → **2**
- 一条纯中文帖最多约 140 字，很容易超

用 `python3 scripts/wlen.py <帖子文本或文件路径>` 核算，**必须 ≤280，建议 ≤275** 留余量。超限就删句，不要扩写、不要拆成两条。常见省字手法：删与首行重复的引入句、收紧铺陈、合并同义的动作描写。

| 字号 | 标题 62／爻辞原文 32／《象》24／《文言》20／译文 19·18／要点 24／书眉与对照 20～21／旁注 19 |
| 主色 | 纸 `#f4efe3`；墨 `#2a2620`／`#4c463c`／`#6f685b`／`#8b8172` 四级；朱砂 `#b03325` **仅本爻与朱印两处** |
| 内容区 | `inset: 54px 76px 66px 76px`（天头小、地脚大），左栏 590px + 细竖分隔线 + 右栏 |
| 输出 | `out/{卦名}{爻名}_知识卡片_封面.png`（相对当前工作目录；要换位置用 `--out`） |

左栏：`卦名 · 第N卦` → `X下Y上 · 说明` → 六爻卦图（自下而上，第 3 爻后虚线分上下卦，本爻朱砂）→ 两行位置注记（第二行用 `<b>` 出中文着重号）。

右栏：`爻名 · 爻辞` + 朱印（卦名一字）→ 爻辞标题两行 → 细线 → **原文 · 译文**界栏 → 所处之位三条 → 底部对照行。

原文界栏采用**古籍经注格式**，自上而下五行，按「原文深、译文浅」分层：

| 行 | 内容 | 字号／墨色 |
|---|---|---|
| 1 | 爻辞原文（`src1`） | 32px，墨1 |
| 2 | 爻辞译文（`trans1`） | 19px，墨3 |
| 3 | 《象》原文（`src2`） | 24px，墨2 |
| 4 | 《象》译文（`trans2`） | 18px，墨3 |
| 5 | 《文言》节引（`src3`） | 20px，墨2，**只引一段（用「……」标明省略）** |

`src2` 缺省时第 3、4 行一并省略；`src3` 只有乾、坤两卦有。《文言》本身不配译文——它只引直接讲爻位的那一段，而爻位信息由「所处之位」用白话承担。译文不限一行：说清楚优先，写长了自然折行，实测各两行仍放得下（容量与溢出处理见 `references/card-design.md` 第 7 节）。

视觉依据、色彩推导与改样式红线见 **`references/card-design.md`**，改模板前先读。

## 5. 易学考据规则

- **必核**：爻辞与《象》逐字准确，联网查权威文本（维基文库《周易》、识典古籍等）。断句有异文时从通行本（如「夕惕若厉，无咎」）。
- **必译**：爻辞与《象》各给白话译文（`trans1` / `trans2`）。译文要求：逐句对应原文、不分叉；用当下口语，不写成半文半白；**以说得明白为准，不限一句、不限字数**——写长了自然折行（实测各两行仍放得下）。溢出先删修辞与重复，不删信息；缩字号是最后手段。译错了比不译更坏——译文与原文对不上的卡片直接作废。
- **《文言》只有乾、坤两卦有**。其余卦 `src3` 留空数组，模板会自动省略该行，不要硬凑。
- **节引**必须用「……」标明，例「……君德也」；不要伪装成逐字全引。**只引一段**，优先取直接讲爻位的句子；被砍掉的义理若重要，交给「所处之位」用白话讲。节引写长了会顶破版面——先用「……」把中间省掉，不硬塞。
- **爻名规则**：阳爻称「九」，阴爻称「六」；位序自下而上为 初／二／三／四／五／上。例：初九、九二、六二、六五、上六。
- **卦图**：阳爻整条实线，阴爻断开两段；`yao_lines` 在配置里按**从上到下**排列（上爻在前），脚本自动在第 3 行后插分界线、按 `hot_from_bottom` 定位本爻。
- **位置解读避争议**：不写三才归属（初二为地等有异说）、不写当位／失位（易家分歧大）。只用注家共识：二为臣位、五为君位、二五得中、下卦之上为危地等。
- **优先引用**《文言》中直接讲爻位的句子（如九三「重刚而不中，上不在天，下不在田」），比泛泛的义理更贴「所处位置」这个主题。
- 底部对照行取**前一爻**的爻辞关键词 → 本爻，形成六爻进程感。**本爻为初爻时无前爻**：改用对卦初爻对举（如坤初六写「乾初九「潜龙勿用」 → 坤初六「履霜」」，合于乾坤并列之例），或写「本卦卦辞 → 初爻」；不要凭空捏一个不存在的前爻。

## 7. 踩坑清单

1. **浏览器裁切**：`chromium --headless=new --window-size=1600,1000` 的实际可视高约 913，不是 1000。所以卡片必须按 900 设计，截图后 `crop(0,0,1600,900)`；否则底部文字会被切掉上半截。
2. **底部行别用绝对定位**：曾用 `position:absolute; bottom:0` 放「对照」行，文本一长就与「所处之位」要点重叠。模板已改正常文档流并压缩间距，两栏总高控制在内容区 780px 内；改 `inset` 或加大上间距都可能让底行被裁。
3. **别让图像模型写中文**：AI 生成的中文必乱码，所有文字由 HTML + 系统字体渲染。
4. **底图水印**：平台生成图右下角带「AI生成」水印，已裁掉底部 80px。直接用 `assets/ink_bg.png`，不要再调图像生成。
5. **复检不可省**：每次渲染后看一眼图，确认高亮爻位正确、底部完整、无重叠。
6. **阴爻高亮的 CSS 特异性**：`.bar.hot` 的红色背景会盖掉 `.bar.yin` 的透明底，让朱红阴爻显示成整条实线。模板里已加 `.bar.yin.hot { background: none; }`，改样式时别删这一行。
7. **朱红配额只有两处**：本爻与朱印。给标签、要点符号、边线加红，本爻就不再是最强音；要强调层级请改墨色明度或字重（`references/card-design.md` 第 4、6 节）。
8. **右栏容量（2026-11-11 实测）**：模板已收紧间距，译文各折到两行时底部对照行仍在内容区内（余约 13px）；节引也折一行就会顶出内容区（墨迹 y 853 > 内容区底边 834）。溢出按阶梯处理：① 删解释性冗字（删修辞、删重复，不删信息）② 节引用「……」截短 ③ 最后手段才收紧行距、缩字号。「所处之位」三条与对照行不删。
9. **中文别套西文排印**：标题不要 `.09em` 大正字距、中文小标签不要 `.26em`；`font-synthesis: none` 别删，否则只有一档字重的系统字体会被合成出糊成墨团的假粗体。
10. **绝不能和日常 Chrome 共用 profile**：无头进程若沿用默认 profile，会和已运行的 Chrome 抢同一个单例锁，Chrome 的 CHECK 直接失败——SIGABRT／SIGTRAP 秒退，崩溃报告里进程名写着「Google Chrome」，用户看到的是自己的浏览器崩了。`render_card.py` 因此每次都用临时 `--user-data-dir`，并优先选 `chrome-headless-shell` 这类专用无头构建。**不要**删掉 `--user-data-dir`，也不要为了省事把用户真实的 profile 路径写进去。
